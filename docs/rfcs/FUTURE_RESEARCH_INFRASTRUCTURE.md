# RFC：未来研究基础设施选项

状态：Draft，本轮不实施

日期：2026-08-28

## 决策

继续使用现有客户端回测、现有 HMM、SQLite、静态 ETF universe 和浏览器内通知。以下五项只保留设计与触发条件，不在本轮增加依赖、数据库、权限或付费服务。

| 选项 | 当前结论 | 启动条件 | 验收门槛 |
|---|---|---|---|
| vectorbt | 暂不引入 | 客户端回测无法满足大规模参数扫描 | 与现有策略在同样本、同成本下结果可对账，并有样本外测试 |
| HMM 扩展 | 保留现有三态模型 | Smart Beta 规则层在多市场持续失效 | 滚动拟合、状态稳定性、泄露检查和对照策略全部通过 |
| TimescaleDB | 继续 SQLite | 单库容量、并发写或时序查询达到已记录瓶颈 | 迁移/回滚、双写对账、恢复演练与成本预算 |
| ETF Universe Manager | 使用已版本化 JSON | 需要动态费率、AUM、折溢价和持仓重叠筛选 | 数据授权、as_of、退市/合并处理和回测生存者偏差评估 |
| 外部通知渠道 | 只保留站内/浏览器通知 | 用户确认目标渠道、告警策略与付费预算 | 最小权限、密钥轮换、去重/静默期、失败重试与订阅退出 |

## 方案顺序

1. 先量化当前瓶颈和错误成本。
2. 在独立分支建立可回滚概念验证。
3. 涉及数据库、权限、付费服务或外部通知时，实施前单独确认。
4. 用可证伪 KPI 决定继续或弃用，不因为工具更新而扩张。
